# 목표
이 저장소는 "비북스-M"(three.js 3D 가상 서점)을 복제한 것이다. 이것을 2018년에 문을 연 실제 동네책방 "역곡동 용서점"의 작은 가상 공간으로 바꾼다. 운영자가 자기 작업실처럼 쓸 공간이다. 공간은 딱 두 곳이다.
1) 용서점 기본 공간 (작고 아늑한 헌책방 느낌의 서점 방)
2) 작은 모임방 (둥근 테이블에 5명 정도가 둘러앉는 방)
두 곳은 문(포털)으로 오간다. 비북스-M의 허브·세미나실·영화관·강연장·1인실은 모두 걷어낸다.

# 작업 방식 (반드시 지킬 것)
- 시작하면 먼저 "계획"을 짧게 정리해 보여준 뒤 바로 진행한다. 질문은 진행을 막는 것만 한다. 인계 문서 7장의 운영자 확인 항목이 비어 있으면, 문서의 ★ 기본값으로 가정하고 진행하되 모든 가정을 README의 "남은 이슈 / 가정한 것"에 적는다. 멈추지 않는다.
- 단계는 인계 문서 5장 순서대로. 단계마다 구현 → `npm run typecheck && npm run build` → Playwright 스크린샷으로 **이미지를 직접 열어 눈으로 확인** → PROGRESS.md 갱신 → 커밋.
- 3D 품질이 최우선이다. 박스 하나로 때우지 말고 bevelBox·taperLeg·projectUV·절차 텍스처·시드 랜덤 변화를 써라. 외부 3D 에셋·이미지 다운로드 금지, 산사(sansatemple.com) 코드·에셋·문구 복사 금지. 새 패키지는 꼭 필요할 때만, 이유를 README에.
- 새 가구(둥근 테이블 등)는 SpaceLayout 필드 + applyLayout + colliders() + 빌더 + bookstore.ts 호출을 한 세트로 추가한다.
- 앉기: 좌석마다 개별 클릭 히트 박스를 만든다(인계 문서 6장 1번). 모임방 5석은 e2e로 5개 모두 클릭→앉기를 검증한다.
- 지우는 작업은 기능 단위로 나눠 하고, 지울 때마다 typecheck. app.ts를 한 번에 크게 지우지 않는다.
- 비북스 상표·URL·코드값·포스터·"써든리"·"서귤"·"독서포인트"가 남지 않게 한다(완료 기준의 grep 확인). 매니저 입장 코드는 비북스 값을 재사용하지 말고 설정/환경변수로 분리한다.
- 모바일(폭 420px)에서 시작→입장→앉기→책 고르기→소리 켜기를 직접 시험한다. 키보드는 Sheet(visualViewport) 방식을 따른다.
- 콘솔 에러 0. 임시 스크립트는 지운다.
- 한국어로 소통하고 한국어로 커밋한다. 보고는 "확인한 것 / 확인하지 못한 것"을 구분해 솔직하게 쓴다.

# 3D 디자인 가이드
- 용서점: 5.5×4.5m 정도의 작은 방. 한쪽 벽을 가득 채운 책장(책등 높이·색·두께가 제각각이고 일부는 눕혀 쌓음), 계산대 + 스툴, 낮은 중앙 매대, 창가 안락의자 읽는 자리(플로어 램프·사이드 테이블), 러그, 식물, 벽 액자, 간판. 따뜻한 전구색 조명, 나무·종이·패브릭 질감. 운영자 사진(docs/reference/)이 있으면 그 색감·배치를 우선한다.
- 모임방: 4.2×4.2m. 방 중앙 지름 1.2~1.4m 둥근 원목 테이블, 72° 간격 의자 5개(전부 테이블 중심을 향함, 각도에 아주 약간의 랜덤), 천장 중앙 펜던트 조명, 한쪽 벽 작은 책장, 소품(찻잔·책).
- 두 방 모두 베벨 몰딩·걸레받이·판재 바닥(줄눈·색 변화)으로 "방"처럼 느껴져야 하고, 카메라가 벽·서가에 가려지지 않아야 한다(작은 방이라 특히 확인).

## 사용 팁 (운영자용)
1. 새 저장소로 복제: 인계 문서 3.1의 명령 그대로.
2. Codex에 프롬프트를 붙이기 **전에** 용서점 사진·간판 글씨·정원 숫자를 `docs/reference/`에 넣고, 문서 7장 질문에 답을 적어 두면 결과가 훨씬 좋다. (없어도 진행은 되지만 ★ 기본값으로 지어낸 부분이 많아진다.)
3. 단계(1→5)마다 스크린샷을 받아 방향을 잡아주면 된다. 한꺼번에 맡기기보다 단계별 확인이 안전하다.
4. 모델 이름이 다르게 표시되면(예: Astra 6) 그 모델의 최대 추론(high) 설정으로 실행한다.
